# orientdigsheetdesk.com

Independent OrientDig product discovery website. Worker reads the complete paginated catalog from kakobuymake.com on demand. Product pages verify matching Weidian IDs, fetch original seller galleries and style images, and place matching main-site source photos below the product details. Source galleries are not represented as verified QC when the source does not label them.

Registration: https://orientdig.com/register?ref=100249252
Purchase route: https://orientdig.com/product?id=ITEM_ID&platform=WEIDIAN&productUrl=&productPwd=
GA4: G-PYD6BSR5Y8, enabled after visitor consent.

Default English, 24 language bundles, separate approximate display currencies, ten main-site categories with descriptions, independent category and product pages, search, favorites, 12 homepage picks and refresh, sixteen FAQ answers, no buying guide, following the latest requirements. Original source product titles are retained.

Run `node scripts/build.mjs`, `node scripts/validate-artifact.mjs`, and `node scripts/check-source.mjs`.
Custom domain DNS, external GitHub, Cloudflare, GSC and Bing binding remain separate from the review deployment.

Latest requirement: no buying guide. All guide routes, homepage sections, navigation links and tutorial assets are removed. Legacy /guide/ redirects to /catalog/. Main product source remains https://kakobuymake.com.

## Image search
Header starts with literal Home and ends with Image search. The image search follows the reference flow: upload/drop/paste JPG/PNG/WEBP/GIF up to20 MB, optimize to max1024px JPEG in the visitor browser, display the reference thumbnail on the left and a change-photo drop zone on the right, then show matching products in three desktop columns (two mobile), 18 per page, maximum48 qualified matches for every product category. Cancel and retry are supported; no category selector is exposed. A module Worker loads pinned Transformers.js 3.8.1 and quantized CLIP vision plus DINOv2-small models (text prototypes are precomputed in the index, so no text model is downloaded), cached after first use. Only the query image is embedded at search time, in the browser; it is not uploaded to a remote search service. Matching uses the complete versioned KakobuyMake visual index in data/visual-index.json.gz rather than traversing the first100 covers. Source identity, semantic category, title conflict checks, CLIP cosine>=.70 and DINOv2 CLS cosine>=.65 gate results for every category, allowing similar products alongside the closest match. Uncertain candidates need DINOv2>=.94 or both CLIP>=.90 and DINOv2>=.88. An ambiguous query text category is resolved using strong image neighbours (CLIP>=.88, DINOv2>=.86, combined>=.89, lead over the next product type>=.06), rather than rejecting the photo before retrieval. Unresolved queries show no sufficiently similar matches. Similarity ranks use .7*detail+.3*semantic, within.30 of the best qualified match, maximum48 for every product category. No filler or low-level color fallback. The index contains main-site IDs, titles, reference prices, cover URLs and quantized normalized feature vectors; original images are not copied into the deployment. Product detail pages still read live source data. Rebuild the index after source catalog changes using scripts/build-visual-index.mjs with @huggingface/transformers@3.8.1 installed (VISUAL_TRANSFORMERS_MODULE and VISUAL_MODEL_CACHE can select a managed runtime). Separate subprocesses perform inference, and a checkpoint resumes completed products. data/visual-index-report.json records indexed coverage and inaccessible images. Index refresh is a maintenance command, not an automatic schedule. The reference website uses a backend POST /api/visual; this implementation uses its own source index and local inference, not that service. Similarity does not establish an identical listing or variation.

Image search layout uses a full-width upload dropzone with centered upload icon, click-to-choose, drag-and-drop and clipboard paste. Accepted images start searching automatically. The old category sidebar and separate Search button are removed.

Product display names use web/product-titles.js in both server HTML and the client, including image-search cards. Existing explicit translations are honored. English source titles remain intact in English; Chinese and other-language display labels are composed from source-backed product type, detected attributes, and preserved Latin brand/model/stock markers using the 24 locale dictionaries. These concise localized catalog labels are not full machine translations of seller marketing text. Chinese mode retains the complete original name. The full original seller title remains expandable on detail pages whenever the display name differs. No remote translation service or translation popup is used.
